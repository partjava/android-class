五、这批改动修掉的三条 + 四条已知遗留（README 和报告都要用）
============================================================

【顺带修掉的问题】
  1. applyWindowInsets() 内边距累加
     原来写的是 getPaddingTop() + bars.top（读-改-写），而 inset 回调会反复触发，
     顶栏会一次比一次高。已改成绝对赋值。
     同类问题在 VideoDetailActivity 里本来就是对的，是视频页抄漏了。
  2. 底部导航高度量得太早（这个肉眼可见）
     measureChrome() 原来只 post() 量一次，读到的是 147px，但 BottomNavigationView
     自己还会因 inset 长到 210px；结果切深色 / 重建后信息行和那条 3dp 进度条
     被底部导航压住。已改成每遍 layout 重量 + setGridPadding() 加幂等保护
     （幂等不能省：不然会反复把用户滚到一半的列表弹回顶部）。
  3. 返回视频页时底部导航高亮停在「商城」
     走 CLEAR_TOP / 返回路径时 onCreate 不执行，复用的实例保持上次的选中项。
     已在 onResume() 里加 syncNavSelection() 静默 setChecked。
     ★ 这一条还没在模拟器上复验过（adb 授权掉了），下次补。

【已知遗留（写进报告的误差分析）】
  1. 单击播放有约 300ms 延迟：onSingleTapConfirmed 必须等双击判定窗口
     （ViewConfiguration.getDoubleTapTimeout()）过去才回调，是区分单双击的固有代价。
  2. 点赞状态不持久化：存在 adapter 的内存里（为了滑动回收后状态还在），
     杀进程 / 重装就丢，没有落盘。
  3. 点赞数上万后 +1 在显示上不可见：formatCount() 会格式化成「1.3万」，
     所以演示数据刻意取 3~4 位数。
  4. 数字压在很亮的封面上对比度不足：右侧操作栏的圆底只垫住图标，
     没垫住图标下面那两行数字；那一段渐变只有约 14% 黑。

【验证环境本身的误差（也可以写进误差分析）】
  · 这台模拟器 adb 掉了授权，导致「返回视频页底部导航高亮」这一项未能复验
  · uiautomator dump 失败时会留下上一次的 ui.xml，读到的是过期层级，
    会把同一个界面描述成两种状态（这次就被误导过一次）
  · adb shell input 的延迟很大（偶尔报 Can't find service: input，
    那一次 tap 是完全没生效）；input swipe 太快会被当成 fling，不翻页
  · 「图片放 drawable/ 会按设备密度放大解码」这个常见说法被实测推翻：
    同一页同路径冷启动，drawable/ 与 drawable-nodpi/ 的 Native Heap
    是 46.2 vs 46.4 MB，无差别（targetSdk >= 28 时保持原始像素解码）。
    所以那 18 张图挪进 nodpi 只是统一资源约定，不是省内存的优化。

附录：实验原理正文草稿（8 条，只讲机制和用法，无代码无图）
============================================================

1. 页面组织与列表局部更新
   项目用 Activity 承载每个页面，底部导航 5 个入口切换到 4 个主页面
   （首页 / 视频 / 商城 / 我的，「添加」只弹提示）。为了让反复切换不堆叠
   返回栈，跳转统一带 CLEAR_TOP | SINGLE_TOP：目标页若已在栈中，系统复用
   原实例并回调 onNewIntent 换数据，而不是新建一个。列表的「局部更新」由
   RecyclerView 承担——切换频道时只换数据源（clear() + addAll() +
   notifyDataSetChanged()），页面本身不重建。同一个列表里要放多种样式的
   条目（纯文字 / 单图 / 三图 / 视频）时，重写 getItemViewType() 返回不同
   类型，onCreateViewHolder 再按类型加载对应布局。

2. 三种 LayoutManager 的选用
   首页信息流是单列 LinearLayoutManager；视频频道是双列等高网格
   GridLayoutManager(2)；商城是两列瀑布流 StaggeredGridLayoutManager(2,
   VERTICAL)。等高还是错落取决于数据：视频封面统一 16:9，等高才排得整齐；
   商品图本身高矮不一，瀑布流才用得上。网格卡片的封面高度不写死，用约束
   比例按实际列宽算出，换屏幕宽度才不会变形。

3. 一屏一条的整屏吸附
   视频页用 ViewPager2 横向分 4 个频道页，推荐页内部再用竖向
   LinearLayoutManager + PagerSnapHelper，松手后自动吸附到最近一整条，
   实现「上下滑切换视频」。

4. 分页与联动动画
   ViewPager2 通过 registerOnPageChangeCallback 回调两个不同粒度的信息：
   onPageSelected 给切换完成的离散位置（用于切高亮），onPageScrolled 给
   0~1 的连续偏移量（用于需要跟着手指走的淡出淡入、配色过渡）。
   前者负责「结果」，后者负责「过程」。

5. 单击与双击的区分
   用 GestureDetector：单击走 onSingleTapConfirmed，双击走 onDoubleTap。
   onSingleTapConfirmed 必须等一个双击判定窗口（系统值约 300ms）过去才会
   回调，这是区分单双击的固有代价。

6. 沉浸式与 insets 适配
   先 setDecorFitsSystemWindows(false) 让内容铺到系统栏底下，再用
   setOnApplyWindowInsetsListener 取 systemBars | displayCutout 的内边距
   补到根视图上；必须用绝对值赋值而不是累加，因为系统栏状态一变这个回调
   就会反复触发。低版本统一走 androidx 的 compat 类，避免用到高版本才有的
   平台 API。

7. 资源体系
   颜色、字号、间距、重复样式都收敛成语义化 token（colors / dimens /
   styles），布局里不写死色值和字号；主题固定浅色并关掉强制反色，保证
   深色设备上表现一致。

8. 模拟播放与动画
   项目不含视频文件也不联网，播放用 Handler.postDelayed 每 200ms 推进 2%
   的进度来模拟；双击点赞的红心用 ViewPropertyAnimator 做放大 + 淡出。
   所有定时器在页面销毁时移除，避免持有页面引用造成泄漏。
